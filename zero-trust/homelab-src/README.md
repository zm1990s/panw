# Homelab 拓扑编辑器

打开同级上层的 `homelab.html` 即可使用，无需启动服务器、联网或安装依赖。`zt-architect.html` 保持原样。

## 编辑与保存

- 顶部“添加区域”按钮创建空区域，不改变已有节点布局。区域属性中可以直接添加节点；节点的“安全域”选项可将已有节点移入，并保留连接。空的自定义区域可以删除，支持撤销。
- 区域颜色支持颜色选择器和 `#RRGGBB` 输入，自动生成同色系浅背景及节点配色；恢复按钮可还原默认配色。自定义区域、颜色及空区域位置保存在 HTML / JSON 中，旧拓扑无需转换。
- 点击区域标题栏或侧边栏区域旁的铅笔按钮，在“区域属性”中修改标题（最多 80 字符）和描述（最多 500 字符）。拖动标题栏仍为整体移动。长文字在图中省略显示，悬浮查看全文。修改同步到搜索、侧边栏和节点区域选项，支持撤销与 HTML / JSON 保存；旧拓扑未设置的区域沿用原名称和描述。
- 点击节点编辑 VM 配额、备注、IP、宿主、服务、Agent、功能、验收和能力映射。
- 拖动节点；按住 Shift / Ctrl / Command 点击可多选。点击空白处解除选择。
- 在选择模式下拖动分区标题栏，可整体移动分区内所有节点（含筛选隐藏的节点），相对位置保持不变，连线同步更新。支持撤销、重做、Esc 取消及触屏拖动。标题栏获得键盘焦点后可用方向键移动 10 单位，Shift + 方向键移动 50 单位；位置随草稿和 HTML / JSON 保存。
- 拖动对齐默认开启：节点与其他可见节点、分区与其他可见分区靠近边缘或中心时自动吸附，并显示临时参考线。多选节点按整体边界对齐且保持相对位置。工具栏磁铁按钮可切换，Alt 可在拖动中临时关闭吸附；开关偏好保存在当前浏览器。参考线不会写入拓扑或导出的图片。
- 使用连线工具依次点击两个节点。点击连线可编辑协议、端口与策略。
- 工具栏支持撤销、重做、平移、缩放、整理布局和按连接类型筛选。滚轮缩放。
- “部署清单”提供完整服务与 Agent 信息；“能力覆盖”可修改原图能力对应的部署方案；“实施阶段”可修改说明和节点状态。
- 字段在提交修改或离开输入框后自动保存到当前浏览器的本地存储。浏览器清理数据、换浏览器或换设备时，草稿可能不可用。
- Chrome / Edge 的主按钮为“覆盖保存”。首次选择已有 `homelab.html` 并授权后，将直接写回目标 HTML，后续保存复用该文件，不下载 JSON。Ctrl / Command + S 同样执行 HTML 保存，并提交正在编辑的输入框。
- 文件选择权由浏览器控制，网页无法仅凭打开的 URL 自动取得写入权限。浏览器会尝试记住当前页面与项目对应的文件句柄；重启、授权过期、移动文件或更换浏览器后可能需要重新选择或授权。
- 导出菜单中的“选择其他 HTML 保存”可更换覆盖目标；之后主按钮写入新选择的文件。
- Firefox / Safari 不支持这里使用的 `showSaveFilePicker` 任意本地文件写入 API。主按钮会显示“另存为 HTML”，下载独立文件，可手动替换原文件；不会伪装为覆盖保存。Firefox 的浏览器私有文件存储不能替代任意本地 HTML 的写入授权。
- 保存状态明确区分“草稿已保存 · HTML 待保存”和“HTML 已保存”。取消选择、拒绝授权或写入失败不会显示保存成功；写入期间新增的修改仍保留待保存状态。
- JSON 下载保留在导出菜单中；文件夹按钮重新导入 JSON。导出 JSON 不代表原 HTML 已更新。
- 导出菜单可保存独立可编辑 HTML，包含当前拓扑，无需其他文件。导出的 HTML 有独立草稿标识；其后在该 HTML 中的编辑仍需再次保存才能更新磁盘文件。
- PNG 可导出全部、当前筛选或多选节点，默认透明背景。连接遵循工具栏当前的连接类型筛选，只包含导出节点之间的连线。
- 节点删除会同步清除相关连接和映射，可撤销。无效 JSON 导入不会覆盖当前规划。

## 初始规划

- 两台 Windows 11：均为 2 vCPU / 4 GiB；分别承担受管终端和安全浏览器 / BYOD 对照实验。对照机可用不同快照分别测试受管与非受管状态。
- 一台 Ubuntu Desktop：暂按 2 vCPU / 4 GiB，可修改。
- Windows 主终端：Cortex XDR、Prisma Access Agent 或 GlobalProtect（二选一）、受支持的 Koi 组件。Ubuntu 按相应产品的 Linux 支持矩阵部署。
- 用户已确认安全产品授权具备；租户地址、具体 SKU、支持的 OS / 内核以及开通状态仍需按实际环境填写。工具不连接控制台、不部署 VM、不修改网络。
- 总计 38 个参考节点，覆盖原架构 65 个模块和 5 个持续验证原理。覆盖表示已规划；节点状态初始全部为待部署。
- 顶部为横向的身份与设备信任；中间仅保留终端、网络、应用与工作负载三列；CNAPP、AI / 安全分析、运营与基础设施位于外围。
- CNAPP 拆分为 CSPM、DSPM、CIEM、CWPP、CDR、攻击路径分析、ASPM、AI-SPM 八个可编辑配套节点，共用云控制面，不另占八台 VM。管理连接关联到各自的数据源和受保护资源。
- 旧版草稿和 JSON 首次打开时会补充 CNAPP 并迁移布局，保留自定义名称、资源、Agent、状态和已有连接；本机草稿迁移前尝试保存一份备份。后续刷新不会重置拖拽位置，也不会重新添加已删除的 CNAPP 节点。
- 服务器暂按 16 核 / 128 GiB / 2000 GiB 参考，不是已确认硬件。全量 26 台 VM 合计 65 vCPU、111 GiB 内存、1456 GiB 虚拟磁盘，另预留 12 GiB 宿主内存。不是要求全部同时部署。
- 本地 SOC、探针、扫描器、沙箱等可以用作商业产品的对照实验。外部控制面无需本地 VM；容器资源计入承载 VM，不重复相加。
- Windows 的 4 GiB 为紧凑配置，应实测 Agent 资源占用并保留扩到 8 GiB 的空间。Windows 11 需要兼容 CPU、UEFI / Secure Boot 能力与虚拟 TPM 2.0。
- 跨域访问流量、身份依赖、遥测、管理、镜像分别展示。部分线条表示逻辑关系而非发起 TCP 连接的方向，详见连接策略字段。
- 参考网络使用管理 10、终端 20 / 25、边界 30、身份 40、工作负载 50、AI 55、IoT 60、运营 70、隔离分析 90 等 VLAN；实际部署前检查与家庭 LAN、VPN、云 VPC 地址是否重叠。

## 源文件

- `template.html`：页面结构。
- `style.css`：布局与样式。
- `seed.js`：VM、服务、Agent、连线、能力映射和初始规划。
- `app.js`：编辑、持久化、导入导出和渲染。
- `file-save.js`：HTML 覆盖写入、文件授权记忆、浏览器兼容回退和保存状态。
- `build.cjs`：读取原架构的能力目录，嵌入 Lucide 图标，生成独立 `../homelab.html`。

修改源文件后，使用 Node.js 运行 `build.cjs`；需可解析 `lucide` 包，可通过 `NODE_PATH` 指定其父目录。构建时保留现有 HTML 内嵌的已保存规划。生成的 HTML 本身不依赖 Node.js 或 Lucide 外部文件。

本机生成命令：

```sh
NODE_PATH=/Users/wangjy/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules /Users/wangjy/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node /Users/wangjy/AI/panw/zero-trust/homelab-src/build.cjs
```
